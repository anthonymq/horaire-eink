## Overview

ESP32-S3 E-Ink dashboard displaying real-time transit (PRIM/IDFM API) and weather (OpenWeatherMap) for Île-de-France. Currently targeting **M5Paper S3** (960x540 parallel EPD) via M5Unified.

## Conventions

- **Serial output**: Use `USE_SERIAL` macro (defined as `Serial`)
- **Display API**: All drawing via `M5.Display.*` (M5GFX)
- **Colors**: `TFT_BLACK`, `TFT_WHITE` (not GxEPD constants)
- **JSON parsing**: ArduinoJson v7 with `JsonDocument` (not v6 `DynamicJsonDocument`)
- **Testable logic**: anything that doesn't need hardware or the network goes in `lib/transit_core` (std::string, no `Arduino.h`) with a test in `test/test_core`
- **Time**: `ESP32Time rtc` for epoch, POSIX `TZ` env var for timezone
- **Icons**: 2-bit format in PROGMEM, rendered via `draw2BitIcon()`

## Anti-Patterns (This Project)

| Pattern | Why Forbidden |
|---------|---------------|
| `GxEPD2` / SPI display code | **REMOVED** - M5Paper S3 uses parallel EPD |
| `display.firstPage()/nextPage()` | Use `M5.Display.startWrite()/endWrite()` |
| GPIO 12 for button | **CONFLICTS with boot** - M5Unified handles button |
| Deciding "on USB" from `M5.Power.isCharging()` only | Charge pin goes idle when the battery is full; use `usbHostConnected()` (USB Serial/JTAG SOF) too, or the device light-sleeps and drops off USB |
| Light sleep without `M5.Display.waitDisplay()` | EPD refresh runs in a background task; sleeping mid-refresh corrupts the panel and keeps HV rails on |
| Global STL containers (`std::map`) | Causes boot crash - use C arrays in config.h |
| `M5.Rtc.setSystemTimeFromRtc()` | Swaps the `TZ` env string around `mktime()` and may leave it wrong; use `timeFromRtc()` in main.cpp |
| `Arduino.h` / `String` in `lib/transit_core` | Breaks the host tests |
| `as any`, `@ts-ignore` | N/A (C++ project) |

## Hardware

**Current**: M5Paper S3 (ESP32-S3, 960x540 EPD, GT911 touch, BM8563 RTC)

| Feature | API |
|---------|-----|
| Display | `M5.Display.*` |
| Button | None usable (`M5.BtnA` is a virtual touch button, disabled) |
| Touch | GT911, INT on GPIO 48: tap = refresh, hold 5 s = setup portal (QR on screen), wakes from light sleep |
| RTC | BM8563 in UTC: set after each NTP sync, system clock restored from it at boot and after each light-sleep wake; its alarm powers the device back on after quiet hours |
| Power | `M5.Power.timerSleep()` (quiet hours) / `powerOff()` (battery empty) cut the power latch; side button powers on |

## Data Flow

```
main.cpp::loop()
  ├─→ readTouch(), readPower(): battery level/USB → batteryState() (critical twice → "charge me" + power off)
  ├─→ quiet hours: on battery → power off until the RTC alarm; on USB → idle
  ├─→ runFetchCycle() (fetchIntervalS(): 2 min, 5 min if nothing within 20 min, ×2 on low battery):
  │     WiFi on → [NTP → RTC] → fetchDepartures() ×N → fetchIncidents() (5 min) → fetchWeather() (30 min) → WiFi off
  ├─→ render() every minute: computeLayout() + countdowns from departureType.expected → drawScreen()
  └─→ idleFor(): waitDisplay() → light sleep until next minute (timer or touch) → clock from RTC
```

## Setup Portal

Hold the screen 5 s:
- **Online** (WiFi connects): WiFiManager web portal on the home network, QR to `http://<ip>/stops` (+ `http://prochain-depart.local/stops` via mDNS). Up to 4 boards: slot order (↑/↓ on the page) is the screen order, size "Grand" (left column, journey names) or "Compact" (right column above the weather). `/update` uploads a new firmware (WiFiManager OTA). The device proxies stop search to PRIM with `API_TOKEN`: `/api/search` → Navitia `v2/navitia/places`, `/api/preview` → `stop-monitoring` grouped by line/quay/platform. Weather location: `/api/cities` → OpenWeatherMap geocoding (`WEATHER_API_KEY`), saved as name + lat/lon in NVS namespace `weather`. Tap the screen or "Terminer" to leave; 10 min idle timeout.
- **Offline**: WiFiManager AP `ProchainDepart-Setup` with a WiFi-join QR (`WIFI:T:nopass;S:...;;`). After a network is saved, it continues straight to the online step (no reboot).

ID mapping: Navitia `stop_area:IDFM:N` → `STIF:StopArea:SP:N:`, `line:IDFM:Cxxxxx` → `STIF:Line::Cxxxxx:`.
Station filter: empty = all; `STIF:Line::...` = line (any type); otherwise RER = platform name, others = LineRef/OperatorRef substring.
E-ink fonts are ASCII only: the page strips accents from titles.

## Incidents

Source: Navitia `v2/navitia/lines/line:IDFM:Cxxxxx/line_reports?filter_status[]=active` per line (the station's `STIF:Line::` filter, else the LineRefs of its departures). The SIRI `general-message` endpoint was not used: it misses incidents and mixes in future works.
- Responses are ~1 MB for an RER line (mostly lift outages), so they are requested gzip (~15x smaller), kept in PSRAM, inflated on the fly with the ROM `tinfl` and parsed one disruption at a time with an ArduinoJson filter.
- Kept: `status == active`, not tagged `Ascenseur`, effect blocking (`NO_SERVICE`, `REDUCED_SERVICE`, `MODIFIED_SERVICE`, `DETOUR`) or delays (`SIGNIFICANT_DELAYS`, `STOP_MOVED`), impacting this station's stop or one of its quays (visit `MonitoringRef`s; a line report also carries other lines' stop closures at shared stops, so those must be titled for this line: "Bus 27 : ..." vs `line_reports[0].line.code`), or the line — and when the line impact has a section (`from`/`to` + routes), only if the station lies between them on one of the routes, and that route then reaches a destination of the station's trains (SIRI `DestinationRef`, i.e. same direction; some incidents list both directions' routes) (ordered stops from `routes/{id}/route_schedules`, cached in RAM; unknown = shown). Text = `title` message, ASCII-folded, line prefix ("RER C : ") removed, deduplicated.
- Display: inverted (black) board title with a warning sign (+ count), first board row gives the text; filled sign = blocking, outline = delays. No gray fills: partial refreshes use the text waveform.

## Layout

`computeLayout()` (lib/transit_core/src/board_layout.h): large boards share the 540 px left column (right column 356 px) (5 rows of 88 for one board, 3 of 65 for two); compact boards stack in the right column at 46 px rows (up to 4, at least 2), and the weather takes the rest. No large board: everything goes left and the weather gets the whole right column with 2 forecast rows. Rows of 76 px and more use the 60 px digits. A layout change forces a full refresh.

Departure rows: countdown, journey name (large boards), `+N` when ≥ 90 s late (expected − aimed), clock time. Cancelled (`DepartureStatus`/`ArrivalStatus` = `cancelled`): "Supprime", struck-through name and timetabled time.

## Migration Notes (GxEPD2 → M5Unified)

| Old (GxEPD2) | New (M5GFX) |
|--------------|-------------|
| `display.init()` | `M5.begin(cfg)` |
| `display.setRotation(3)` | `M5.Display.setRotation(1)` |
| `display.getTextBounds()` | `M5.Display.textWidth()` + `fontHeight()` |
| `GxEPD_BLACK/WHITE` | `TFT_BLACK/WHITE` |
| `display.firstPage()/nextPage()` | Direct draw + `display()` |
| GPIO button handling | `M5.BtnA.wasPressed()` |
